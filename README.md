# コンピュータ部 作品展 2026 — eclipse

三田国際科学学園 コンピュータ部の作品展サイト。

**太陽系はひとつだけ。** 惑星＝ジャンル、衛星＝作品。惑星をクリックすると太陽系がそこへ寄っていき、
空いた場所に衛星が現れます。場面の差し替えはしていません。動くのはカメラだけです。

- ビルド不要。HTML / CSS / 素の JavaScript のみ
- npm も Node も不要。GitHub Pages に置くだけで動く
- 作品データは Google スプレッドシートから自動取得（未設定ならサンプル表示）
- アンケートは見た目を自作し、送信先は Google フォーム

```bash
cd computer-club-mita && python3 -m http.server 5173
```

`http://localhost:5173` を開きます。Windows なら `python -m http.server 5173`。

`fetch` を使うため、ファイルを直接ダブルクリックではなく簡易サーバー経由で開いてください。

### 背景動画について

`assets/video/computopia2.mp4` は **7.4MB / 61秒 / 1280×720 / 24fps / 無音**です。
元の `computopia2.mov`（72MB / 1920×1080）を ffmpeg で圧縮したものです。

```bash
ffmpeg -i computopia2.mov -vf "scale=1280:-2,fps=24" -c:v libx264 -crf 30 -preset slow -an -movflags +faststart computopia2.mp4
```

`-an` で音声を落としています（背景動画なので音は鳴らしません）。
`+faststart` を付けているので、全部読み終わる前に再生が始まります。
撮り直したときは同じコマンドで作り直してください。

元の `.mov` は `.gitignore` で除外しています。QuickTime のコンテナは
Firefox が再生しないことがあるためで、`.mp4` だけを置けば全ブラウザで動きます。
読めない環境・データ節約モード・動きを控える設定では、観測窓（`.scope-lens`）の地の色（緑黒のグラデーション）だけで成立します。

## 2-1. ホームの導入（ようこそ → ローディング → ホーム）

`index.html` だけ、最初にこの導入が入ります。

1. 黒い画面に「コンピュータ部へようこそ」と「特設サイトへ」ボタンだけ
2. 押すと、輪が回るローディング画面になり、昆布の豆知識が出る
3. 終わると、いつものホームが現れる

出るのは次の2つのときだけです。

| 操作 | 導入 |
|---|---|
| はじめての訪問 | 出る |
| **ブラウザの再読み込み（F5 など）** | 出る |
| サイト内のリンクで「ホーム」に戻る | 出ない |

見た記録は `localStorage`（`ccm-intro-seen`）に残します。行き来のたびに
あの黒画面から始まると煩わしいのでリンク移動では出しませんが、わざわざ
再読み込みするのは「もう一度最初から見たい」という意思表示なので、
そのときは何度でも出します。判定は Navigation Timing API の
`performance.getEntriesByType('navigation')[0].type` を見ています。

JS が動かない環境や、`localStorage` が読めない環境（プライベートモード
など）では最初から出さず、直接いつものホームが表示されます。

> **注意**: `.intro` のようにクラス側で `display` を指定した要素を
> `hidden` 属性で隠そうとすると、ブラウザ標準の `[hidden]{display:none}`
> は詳しさが最低なので**負けます**。見えているのに JS が処理を繋いで
> いない板が最前面に居座り、押しても無反応、という壊れ方をします。
> この事故が3回起きたので、`style.css` の冒頭で
> `[hidden]{display:none !important}` を一度だけ効かせてあります。

豆知識の文言を変えたいときは `index.html` の `TIP` を書き換えてください（いまは1本だけ）。

## 6. 作品データをつなぐ

### 6-1. 作品投稿フォームを作る

Google フォームで以下の質問を作ります。**質問文は候補のどれかに合わせてください**
（`config.js` の `sheetColumns` が部分一致で列を探します）。

| 質問文の例 | 必須 | 内容 |
|---|---|---|
| 作品名 | ● | 作品のタイトル |
| 制作者 | ● | 学年+名前など |
| カテゴリ | ● | 音楽 / 映像 / プログラミング / モデリング / その他 |
| 作品URL | ● | Scratch / YouTube / Google ドライブ / サイトの URL |
| サムネイル | | 画像の URL。空でも構いません |
| 説明 | | 作品についての文章 |
| ドキュメント | | 制作資料（Google ドキュメント）の URL |

カテゴリは表記ゆれを吸収します。「ゲーム」「Scratch」「Web」→ プログラミング、
「動画」「movie」→ 映像、「3D」「Blender」→ モデリング、「イラスト」「絵」→ その他。
カテゴリが空でも URL から自動判別します。

### 6-2. 回答をサイトに接続する

1. 回答スプレッドシートを開く
2. **ファイル → 共有 → ウェブに公開**
3. 形式を **カンマ区切り（.csv）** にして公開
4. 出てきた URL を `config.js` の `sheetCsvUrl` に貼る

> 「ウェブに公開」した表は URL を知っていれば誰でも読めます。個人情報は入れないでください。

失敗するとコンソールに `[CCM] スプレッドシートに繋がらないため、サンプルを表示しています。` と出ます。

## 6-9. 裏側（スプレッドシート）をつなぐ

**アンケートの保存・作品へのひとこと・ハートの数**の3つを、
Google スプレッドシート1つで受け持ちます。無料で、カードの登録もいりません。

繋がなくてもサイトは普通に動きます。ひとこと欄とハートの数が出なくなるだけです。

### 手順（10分ほど）

1. **スプレッドシートを新しく1つ作る**（名前は「昆布観測島 2026」など何でも）
2. **拡張機能 > Apps Script** を開く
3. 出てきたエディタの中身をぜんぶ消して、
   [`docs/gas-backend.gs`](docs/gas-backend.gs) の中身をまるごと貼り、保存
4. 右上の **デプロイ > 新しいデプロイ**
   - 種類: **ウェブアプリ**
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員** ← ここが「自分のみ」だと繋がりません
5. 初回は「承認が必要です」と出るので、自分の Google アカウントで許可する
   （「安全ではないページ」と警告が出ますが、自分で書いたスクリプトなので進んで大丈夫）
6. 出てきた `https://script.google.com/macros/s/……/exec` をコピー
7. `assets/js/config.js` の **`apiUrl`** に貼る

```js
apiUrl: 'https://script.google.com/macros/s/AKfycb.../exec',
```

**確認**: その URL をブラウザでそのまま開いて
`{"ok":true,"message":"昆布観測島の裏側は動いています",...}` と出れば成功です。

### できるシート

貼り付けたスクリプトが、必要になった時点で自動で作ります。

| シート | 中身 |
|---|---|
| `アンケート` | 日時 / 満足度 / あなたについて / 一番よかった作品 / ジャンル / 興味 / どこで知ったか / 自由記述 |
| `コメント` | 日時 / 作品 / なまえ / 本文 / 公開 / 判定 / 理由 / 侮辱 / 不適切 / 種類 / 端末ID / FirebaseID |
| `ハート` | 日時 / 作品 / 端末ID / 増減 |

古い `コメント` シート（5列）は、そのまま使えます。足りない見出しは右に自動で足されます。

### ひとことを消したい・載せたいとき

[6-10](#6-10-ひとことの自動審査jev) を見てください。`コメント` シートの **「公開」列**を切り替えて、
メニュー「昆布観測島 > ひとことの公開／非公開を反映する」を押します。

### ハートの数え方

表示される数は Firebase です（押した瞬間にサーバー側で ±1）。
Firebase のルールで **±1 以外の書き換えは弾く**ので、数字を直接いじって増やすことはできません。

押したかどうかはその画面の中（メモリ）だけが覚えています。会場の共用パソコンで
次の人が押せるよう、**再読み込みすると押していない状態に戻ります**。そのため同じ人が
何度も数を増やせます。厳密な本人確認はしていないので、**おおよその人気度**として見てください。
押した記録は、シートの `ハート` にも1行ずつ残ります。

### コードを直したとき

Apps Script を編集したら、**もう一度デプロイし直す**必要があります。
「デプロイ > デプロイを管理 > 鉛筆マーク > バージョン: 新バージョン > デプロイ」。
URL は変わりません。

## 6-10. ひとことの自動審査（Jev）

作品への「ひとこと」は、載せる前に **Jev**（TypeSafe AI の判定用モデル）が読みます。
Jev は文章を書くモデルではなく、決めた問いに「どれか・何％か」で答えるモデルです。
1件につき3つを同時に聞いています（`docs/gas-backend.gs` の `jevRequest()`）。

| 問い | 形式 | 中身 |
|---|---|---|
| `kind` | choice | 称賛 / **作品への指摘・改善案** / 質問 / 侮辱 / 無関係 / 不適切 のどれか |
| `attacks_person` | noul | 作者や人を侮辱・攻撃しているか（はいの確率） |
| `unsafe` | noul | 学校の公開サイトに載せてはいけない内容か（個人情報・性的・暴力など） |

**方針：辛口でも、作品についての指摘は載せる。人を貶める言い方が混ざれば載せない。**
「操作が分かりにくい」「正直単調だった、後半に変化がほしい」は載ります。
「つまらない、作ったやつセンスない」は載りません。

| 結果 | 条件（`TH` で調整） | 投稿した人に出る文 | 表示 |
|---|---|---|---|
| 公開 | 侮辱・不適切がどちらも 0.3 未満、かつ 称賛＋指摘＋質問 ≥ 0.7 | ありがとうございます。載せました。 | すぐ載る |
| 確認待ち | 侮辱・不適切が 0.3〜0.6 / 種類があいまい / Jev に繋がらない | 部員が確認してから載せます。 | 載らない |
| 却下 | 侮辱・不適切が 0.6 以上 / 無関係 0.7 以上 | 作品への指摘は大歓迎です。人を傷つける言い方になっていないか… | 載らない（書いた文は消えずに残る） |

**審査できなかったものは載せません**（キー未設定・Jev の障害・Firebase に書けない、はすべて確認待ち）。
同じ端末からの連投は 15 秒に1件・1時間に 12 件までです。

### 仕組み

ブラウザ → Apps Script（Jev で審査）→ 公開してよいものだけ Apps Script が Firebase に書く → ブラウザは Firebase から読む。
Jev の API キーはブラウザに置けない（公開サイトなので誰でも見られる）ため、必ず Apps Script を通します。
Firebase のルールで **ブラウザからの直接の書き込みは閉じて**あります。

### 用意（15分ほど）

1. TypeSafe（https://typesafe.ai ）で API キーを取る（2026年9月時点は順番待ちの早期アクセス）
2. Apps Script の **プロジェクトの設定 > スクリプト プロパティ** に `JEV_API_KEY` = キー を追加
3. Firebase に書く権限を Apps Script に渡す。**どちらか1つ**:
   - **A（おすすめ・秘密の値なし）**: プロジェクトの設定で「appsscript.json をエディタで表示する」をオンにし、
     `appsscript.json` の中身を [`docs/appsscript.json`](docs/appsscript.json) に置き換える。
     Apps Script を持っている Google アカウントが、Firebase プロジェクトのオーナー（または編集者）であること
   - **B**: Firebase の「プロジェクトの設定 > サービス アカウント > データベースのシークレット」を
     スクリプト プロパティ `FIREBASE_SECRET` に入れる（古い方式。秘密の値なので人に見せない）
4. `docs/gas-backend.gs` を貼り直して、**新バージョンでデプロイ**（URL は変わらない）
5. Firebase の「Realtime Database > ルール」に [`docs/firebase-rules.json`](docs/firebase-rules.json) を貼って公開
6. スプレッドシートを開き直すとメニュー **「昆布観測島」** が出るので、
   **「Jev と Firebase の接続を確認する」** を押す。ふつうの感想・辛口の指摘・悪口の3例の判定が出ます
7. 必要なら **「5分ごとに自動で反映する」** を1回押す（下の手直しが自動で反映されるようになる）

### 部員の手直し（すり抜け・取りこぼし）

`コメント` シートに全件が残ります。**「公開」列**を切り替えて、メニュー
**「ひとことの公開／非公開を反映する」**（または5分ごとの自動反映）で Firebase に反映されます。

| したいこと | 操作 | 反映後の「判定」 |
|---|---|---|
| 確認待ち・却下を載せる | 「公開」を `TRUE` に | `approved` |
| 載ったものを取り下げる | 「公開」を `FALSE` に | `removed` |

「判定」が空の行（この仕組みより前の古い投稿）には触りません。

Firebase コンソールの `comments` で一度目を通してください。

**しきい値の調整**: 「侮辱」「不適切」「種類」列に Jev の数字が残ります。

| # | 質問 | 形式 | 送信キー |
|---|---|---|---|
| 1 | 展示はいかがでしたか | 5段階・必須 | `rating` |

## 7-1. タブのタイトルと favicon

ヘッダーの名前・アイコン、ブラウザタブのタイトルとも「// 昆布観測島」です。
アイコンは `assets/favicon.png`（部員が作った今年のアイコン、512×512）を
ヘッダーと favicon の両方で使い回しています。差し替えたいときは
このファイルを置き換えるだけで、5ページ全部に反映されます。

**スクロールするページ（Q&A・アンケート）だけ、ナビの後ろに黒い膜**（`pages.css` の
`.page-doc .nav::before`）を敷いています。膜が無いと、下から上がってきた本文が
ナビの文字と重なって読めません。バーの中は真っ黒で、**溶けるのはバーの外側 34px だけ**。
境界線は引いていません（線を1本引くだけで箱に見えてしまうため）。
ホーム・作品一覧・マップはスクロールしないので膜を敷かず、映像や食の光を上端まで見せています。

**元画像は黒地なので、背景を透過させた PNG に変換してあります。**
黒地のまま丸く切り抜いて置くと、ナビが透けている分そこだけ黒い円が
浮いて見えました。明るさからアルファを作る（しきい値 6〜40 で滑らかに
立ち上げる）ことで、線のアンチエイリアスを保ったまま地を抜いています。
撮り直した画像に差し替えるときも、同じ処理をかけてから置いてください。

**緑はロゴの色（`#00ff00`）1色に統一しています。** `style.css` の `--acid` と、
半透明で使うときの `--acid-rgb`（`rgba(var(--acid-rgb), .3)` のように書く）の2つだけです。
マップ（`map.js` の `ACID`）も同じ色です。食の縁の光も、この緑の濃淡だけで作っています。
新しい色を足すときも `var(--acid)` から作ってください。

いま居るページのリンクには `aria-current="page"` を付けています（読み上げで現在地が分かる）。

表記は場所で使い分けています。**ブランドとして立つところ**（ナビ・
タブのタイトル・フッター・noscript の見出し）は `// 昆布観測島`、
**文章の中**は読みやすさを優先して `昆布観測島`（スラッシュなし）です。

## 7-2. サイト全体の演出

amicro（React 向けのマイクロインタラクション集。CLI は実行不能だったため
ブラウザで実物を触って着想だけ持ち帰った）を参考に、素の CSS/JS で作った。

**ホーム** — 見出し・作品数などが、開いた瞬間に順番で浮かび上がる
（`site.js` の `reveal()`）。作品数・制作者数はデータが届いた瞬間に
0 から数え上げる（`countTo()`）。

**Q&A** — 質問のかたまりが、スクロールで画面に入るたびに現れる。
`[data-reveal]` を付けるだけで動く共通の仕組み（`IntersectionObserver`）。

**アンケート** — 選んだ瞬間だけチップやボタンが弾む（`.pop`、2段の
バネ状キーフレーム）。送信できると、輪が現れてから影が滑り込み
食になる、サイトのテーマをなぞった感謝画面。

**作品一覧** — 開いた瞬間だけ、5つの惑星が順番に浮かび上がる
（`entrancePlanets()`）。ズームで惑星を隠す通常の動きを壊さないよう、
CSS トランジションを使い、終わったら後片付けをして元の挙動に戻す。

**ボタン全般** — CTA はカーソルに少しだけ寄る（磁石）。当たり判定はいじらない、
見た目だけの演出。（押した点から輪が広がる演出は、既製品っぽさが強かったので外した）

**全画面再生**（`works.html` の `.player`） — **いいね**と**ひとこと**。
いいねは輪郭のハートが、押した瞬間だけバネで弾んで塗りつぶされ、
小さな光の粒が散る。数は Firebase で数える（[6-9 ハートの数え方](#ハートの数え方)）。
共有ボタンは置いていない。ひとことは [6-10](#6-10-ひとことの自動審査jev) の審査を通る。

**動きの考え方（2026-09）** — 動きはばらまかず、**見せ場を1つ**＋**人の操作に応える動き**にしている。

| 動き | どこ | 仕組み |
|---|---|---|
| **食の終わり**（見せ場） | ホームを開いた瞬間 | 観測窓を覆っていた月の影が左下へ滑り去り、右上で最後の光が一瞬ひかる。縁のロゴが回り込んで止まり、ゆっくり回り続ける（`pages.css` の `egress` / `flare` / `ringIn`）。初回の導入画面の間は待つ |
| 見出しが一文字ずつ立ち上がる | 各ページの見出し | `[data-split]` を付けるだけ（`site.js` の `splits()`）。作品一覧でジャンルを切り替えると、変わった見出しがもう一度立ち上がる |
| 字の読み出し | 観測ログ・開催までの日数 | でたらめな字が左から本来の字に落ち着く（`CCMSite.decode()`） |
| 奥行き | 星空・食の光・観測窓 | カーソルに合わせて星と光がずれ、観測窓はカーソルの方へ少し傾く（`pointer()`。マウスのときだけ） |
| ナビの下線 | 全ページ | 1本だけ。狙ったリンクへ滑り、離れると現在地に戻る（`navInk()`） |
| 粒子 | 全ページ | ごく薄いフィルムの粒（`html::after`） |

すべて `prefers-reduced-motion` を見ていて、動きを控える設定では
最終状態だけが出る（月の影も出さない）。ホームの映像も、動きを控える設定と
データ節約モードのときは流さない（地の色だけになる）。

## 8-1. 更新してもブラウザに反映されないとき

GitHub Pages は CSS / JS に `Cache-Control: max-age=600`（10分）を付けます。
そのため push 直後は、ブラウザが古い版を握ったままのことがあります。

5ページ（`*.html`）の `<link>` `<script>` には `?v=更新した日時` を付けてあります。
**CSS か JS を書き換えたら、全ページの数字を同じ値に更新してから push してください。**
番号が変われば別のURL扱いになるので、10分を待たずに反映されます。
ページごとに番号がずれていると、ページによって古いファイルが混ざるので、必ず全部まとめて。

```bash
V=$(date +%Y%m%d%H%M%S)
sed -i "s/?v=[0-9]*/?v=$V/g" *.html
```

Windows の PowerShell なら：

```powershell
$V = Get-Date -Format yyyyMMddHHmmss
Get-ChildItem *.html | % { (Get-Content $_ -Raw -Encoding UTF8) -replace '\?v=\d+', "?v=$V" | Set-Content $_ -NoNewline -Encoding UTF8 }
```

それでも直らないときは、ブラウザの強制再読み込み（Windows: `Ctrl+Shift+R`）を。

## 10. 仕組みのメモ（あとで直す人へ）

**場面はひとつ。** 衛星は最初から惑星の子要素として DOM に在り、普段は `opacity:0` です。
ジャンルを切り替えても要素は作り直しません。

**カメラ** は `.sys` の `transform` ひとつです。押した惑星が中心へ来るよう
`translate(-K·v) scale(K)` を当てています。`v` は押した瞬間の惑星の位置ベクトルで、
角度は**公転アニメーション自身の時計**（`getAnimations()[0].currentTime`）から読みます。
`performance.now()` を使うと、公転を止めている間にずれます。

**等間隔配置** は `seat`（静的な回転）で行います。`animation-delay` による位相ずらしは
環境によって効かず、全部が重なりました。

**名札の位置** は `left` で指定するため**拡大前のローカル座標**で解釈されます。
画面上の見た目の距離を指定したいときは `K` で割ってください（`app.js` の `--fo`）。

**遷移の方向** で速さを変えています。衛星は現れるとき遅く（寄り終わってから）、
消えるときは即座。CSS は「変化後の状態に書かれた設定」が使われることを利用しています。

**配置の寸法** は `layout()` が画面幅から毎回計算します。見出し・右パネル・ガイドを
避けられるまで軌道半径を縮めるので、狭い画面でも文字と衝突しません。

**作品は「傾いた円」の上に等間隔で並び、それを透視投影で落としています**（`proj`）。
楕円を直接描くやり方だと、手前どうしの大きさの差がほとんど出ませんでした。
円＋透視にすると、カメラに近いものほど非線形に大きくなるので、
隣り合っていても手前の1つだけがはっきり大きく見えます。実測で **0.68〜1.86倍**、
いちばん手前といちばん奥で **2.7倍**の差が出ます。

位置・大きさ・明るさ・重なり順は、すべてこの1つの投影から出しています。
レイヤーは奥から順に **奥の軌道線 6 → 奥の作品 12〜19 → 中心 20 →
手前の軌道線 21 → 手前の作品 24〜31**。作品はいつでも軌道線より上に来るので、
線がサムネイルを横切ることはありません。
軌道線も手前半分と奥半分で別々の `<svg>` に分け、同じレイヤー構成で前後へ
振り分けています（円を透視で落とすと単純な楕円にならないため、CSS の楕円ではなく
点を打って描いています）。見た目は前後で変えていません（同じ色・同じ太さ）。
**中心の丸に重なる範囲を描かないのは奥側だけ**です。手前側は丸より上のレイヤーに
あるので、隠す必要がなく、そのまま丸の上を通って描かれます
（最初、手前側にも同じ除外をかけてしまい、見下ろし角によっては
線が途中で切れて見える不具合になっていました）。円は自分の軸で回しても
形が変わらないので、横回転では引き直さず、見下ろし角が変わったときだけ描き直します。

**カメラは上下左右に振れます**（`wireDrag`）。横に引くと `yaw`、縦に引くと `pitch`。
真上から見下ろすところ（`pitch` 88°）まで振れるので、奥の作品が回ってくるのを
待つ必要がありません。中心の位置は動かさず、絵の向きも変えません
（いつでもこちらを向いたまま）。視点を動かすと画面下に「カメラをリセット」が
せり上がり、押すと 0.76 秒かけて既定の角度へ戻ります。

**クリックとドラッグの切り分け**：`setPointerCapture` は使っていません。
使うと `click` の宛先が `#scene` に変わってしまい、作品をクリックできなくなります。
かわりに 5px 動くまでは「クリック」として扱い、それを超えたらドラッグに切り替えて、
離した直後の `click` だけを打ち消しています。

**線は作品の丸とも重なりません。** 最初はパスの点を毎コマ削り直す
方式でしたが、角度のサンプリング（2度刻み）でしか判定できないため、
線が段々になって消える・現れるがカクついて見えました。
**SVG の `<mask>` に切り替えています。** ぼかしのかかった放射グラデーションの
円を、中心と各作品の位置に重ね、円の座標・半径を毎コマそのまま動かすだけです。
円の位置は作品の連続的な動きに直結しているので、線は角度の刻みに縛られず
なめらかに透明になります。線の形そのもの（`ringPath` の出力）は
見下ろし角が変わったときしか再計算しません。

**左右の継ぎ目（手前と奥がちょうど入れ替わる点）は、必ず同じ座標で
つながる**ようにしています。厳密な不等号（z>=0 / z<0）で振り分けると、
ちょうど境界の点をどちらか片方しか含まず、継ぎ目に小さなすき間が
できていました。境界に許容誤差を持たせ、両方の経路に含めています。

**輪の定員**は式ではなく `worstGap` で実測します。36 通りの位相で全組み合わせを測り、
直径の 0.26 倍のすき間が残らない配置は採用しません。入らなければ作品を少しずつ小さくし、
それでも入らなければ外側にもう1本の輪を足します（`planShells`）。

**衛星の中身＝作品のサムネイル画像**です。`.lens` という円い枠にはめ込み、
縁をそのジャンルの色（`--cg`）で締めています。`--cg` は作品ごとにずらさず
`config.js` の `hue` そのままなので、色を見れば所属ジャンルが分かります。

**枠の中で絵を 1.12 倍しています。** 上下に黒い余白が残らないようにするためです。
YouTube のサムネイルも `hqdefault`（4:3 の額縁に 16:9 を入れたもので黒帯が焼き込まれている）
ではなく `mqdefault`（素の 16:9）を取ります。拡大は `.lens` が切り抜くので枠は太りません。
取得できなかった作品だけ `thumbs.js` が代替の絵を描きます。ジャンルごとに絵柄が違い
（音楽＝波形、映像＝フィルム、プログラミング＝コード行、モデリング＝立方体、その他＝図形）、
作品名のハッシュで細部が変わるので、同じ絵が並ぶことはありません。

**ページの切り替え**は「食」に合わせています。前の面は奥へ引いてぼけながら消え、
次の面は中心から円で開きます（`ecOut` / `ecIn`）。View Transitions が使える環境は
CSS の `@view-transition` に任せ、使えない環境では `site.js` が同じ動きを `body` に当てます。
JS は「対応している」ではなく**「対応していない」方に印（`.novt`）を付けます** —
印が付く前の一瞬に代わりの動きが走ってしまうのを避けるためです。
`prefers-reduced-motion` のときは短い明滅だけになります。

**星** も `site.js` が撒きます。最小間隔 76px を守る棄却サンプリングなので固まりません。
作品一覧だけは `app.js` が自前で撒きます（太陽系の再配置と同時に撒き直すため）。
