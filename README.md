# コンピュータ部 作品展 2026 — eclipse

三田国際科学学園 コンピュータ部の作品展サイト。

**太陽系はひとつだけ。** 惑星＝ジャンル、衛星＝作品。惑星をクリックすると太陽系がそこへ寄っていき、
空いた場所に衛星が現れます。場面の差し替えはしていません。動くのはカメラだけです。

- ビルド不要。HTML / CSS / 素の JavaScript のみ
- npm も Node も不要。GitHub Pages に置くだけで動く
- 作品データは Google スプレッドシートから自動取得（未設定ならサンプル表示）
- アンケートは見た目を自作し、送信先は Google フォーム

---

## 1. 動かす

```bash
cd computer-club-mita && python3 -m http.server 5173
```

`http://localhost:5173` を開きます。Windows なら `python -m http.server 5173`。

`fetch` を使うため、ファイルを直接ダブルクリックではなく簡易サーバー経由で開いてください。

### 背景動画について

`assets/video/computopia2.mp4` は **7.4MB / 61秒 / 1280×720 / 24fps / 無音**です。
元の `computopia2.mov`（72MB / 1920×1080）を ffmpeg で圧縮したものです。

```bash
ffmpeg -i computopia2.mov -vf "scale=1280:-2,fps=24" -c:v libx264 -crf 30 -preset slow -an -movflags +faststart computopia2.mp4
```

`-an` で音声を落としています（背景動画なので音は鳴らしません）。
`+faststart` を付けているので、全部読み終わる前に再生が始まります。
撮り直したときは同じコマンドで作り直してください。

元の `.mov` は `.gitignore` で除外しています。QuickTime のコンテナは
Firefox が再生しないことがあるためで、`.mp4` だけを置けば全ブラウザで動きます。
どちらも読めない環境では、`.filmbg` の地の色（緑黒のグラデーション）だけで成立します。

## 6. 作品データをつなぐ

### 6-1. 作品投稿フォームを作る

Google フォームで以下の質問を作ります。**質問文は候補のどれかに合わせてください**
（`config.js` の `sheetColumns` が部分一致で列を探します）。

| 質問文の例 | 必須 | 内容 |
|---|---|---|
| 作品名 | ● | 作品のタイトル |
| 制作者 | ● | 学年+名前など |
| カテゴリ | ● | 音楽 / 映像 / プログラミング / モデリング / その他 |
| 作品URL | ● | Scratch / YouTube / Google ドライブ / サイトの URL |
| サムネイル | | 画像の URL。空でも構いません |
| 説明 | | 作品についての文章 |
| ドキュメント | | 制作資料（Google ドキュメント）の URL |

カテゴリは表記ゆれを吸収します。「ゲーム」「Scratch」「Web」→ プログラミング、
「動画」「movie」→ 映像、「3D」「Blender」→ モデリング、「イラスト」「絵」→ その他。
カテゴリが空でも URL から自動判別します。

### 6-2. 回答をサイトに接続する

1. 回答スプレッドシートを開く
2. **ファイル → 共有 → ウェブに公開**
3. 形式を **カンマ区切り（.csv）** にして公開
4. 出てきた URL を `config.js` の `sheetCsvUrl` に貼る

> 「ウェブに公開」した表は URL を知っていれば誰でも読めます。個人情報は入れないでください。

失敗するとコンソールに `[CCM] スプレッドシートに繋がらないため、サンプルを表示しています。` と出ます。

## 7. アンケートをつなぐ

質問は6問です。**送信先が未設定でも、入力から感謝画面まで通しで動きます**
（そのときは感謝画面に「保存されていません」と出ます。部員に見せる分にはこのままで大丈夫です）。

| # | 質問 | 形式 | 送信キー |
|---|---|---|---|
| 1 | 展示はいかがでしたか | 5段階・必須 | `rating` |
| 2 | あなたについて | 1つ選択 | `who` |
| 3 | 一番よかった作品 | 作品から選択 | `favWork` |
| 4 | どのジャンルが面白かったですか | 複数選択（読点でつないで送信） | `genre` |
| 5 | コンピュータ部に興味を持ちましたか | 1つ選択 | `interest` |
| 6 | この展示をどこで知りましたか | 1つ選択 | `found` |
| 7 | 感想・部員へのメッセージ | 自由記述 1000字 | `comment` |

送信すると、書いてもらった内容を一言にして返します
（例:「満足度は『最高』、一番は『リズム・オブ・ミタ』、メッセージを 17文字で受け取りました。」）。

### 実際に集計するには

1. Google フォームで上の7問を作る
2. プレビューでソースを表示（Mac: `⌘ + option + U`）し `entry.123456789` を7つ控える
3. フォーム URL の `/viewform` を `/formResponse` に変える
4. `config.js` に転記

```js
survey: {
  formAction: 'https://docs.google.com/forms/d/e/XXXXX/formResponse',
  entries: {
    rating:   'entry.111111111',
    who:      'entry.222222222',
    favWork:  'entry.333333333',
    genre:    'entry.444444444',
    interest: 'entry.555555555',
    found:    'entry.666666666',
    comment:  'entry.777777777'
  }
}
```

## 8-1. 更新してもブラウザに反映されないとき

GitHub Pages は CSS / JS に `Cache-Control: max-age=600`（10分）を付けます。
そのため push 直後は、ブラウザが古い版を握ったままのことがあります。

`index.html` `qa.html` `survey.html` `works.html` の `<link>` `<script>` には
`?v=更新した日時` を付けてあります。**CSS か JS を書き換えたら、この数字を
更新してから push してください。** 番号が変われば別のURL扱いになるので、
10分を待たずに反映されます。

```bash
V=$(date +%Y%m%d%H%M%S)
sed -i "s/?v=[0-9]*/?v=$V/g" index.html qa.html survey.html works.html
```

それでも直らないときは、ブラウザの強制再読み込み（Windows: `Ctrl+Shift+R`）を。

## 10. 仕組みのメモ（あとで直す人へ）

**場面はひとつ。** 衛星は最初から惑星の子要素として DOM に在り、普段は `opacity:0` です。
ジャンルを切り替えても要素は作り直しません。

**カメラ** は `.sys` の `transform` ひとつです。押した惑星が中心へ来るよう
`translate(-K·v) scale(K)` を当てています。`v` は押した瞬間の惑星の位置ベクトルで、
角度は**公転アニメーション自身の時計**（`getAnimations()[0].currentTime`）から読みます。
`performance.now()` を使うと、公転を止めている間にずれます。

**等間隔配置** は `seat`（静的な回転）で行います。`animation-delay` による位相ずらしは
環境によって効かず、全部が重なりました。

**名札の位置** は `left` で指定するため**拡大前のローカル座標**で解釈されます。
画面上の見た目の距離を指定したいときは `K` で割ってください（`app.js` の `--fo`）。

**遷移の方向** で速さを変えています。衛星は現れるとき遅く（寄り終わってから）、
消えるときは即座。CSS は「変化後の状態に書かれた設定」が使われることを利用しています。

**配置の寸法** は `layout()` が画面幅から毎回計算します。見出し・右パネル・ガイドを
避けられるまで軌道半径を縮めるので、狭い画面でも文字と衝突しません。

**作品は「傾いた円」の上に等間隔で並び、それを透視投影で落としています**（`proj`）。
楕円を直接描くやり方だと、手前どうしの大きさの差がほとんど出ませんでした。
円＋透視にすると、カメラに近いものほど非線形に大きくなるので、
隣り合っていても手前の1つだけがはっきり大きく見えます。実測で **0.68〜1.86倍**、
いちばん手前といちばん奥で **2.7倍**の差が出ます。

位置・大きさ・明るさ・重なり順は、すべてこの1つの投影から出しています。
レイヤーは奥から順に **奥の軌道線 6 → 奥の作品 12〜19 → 中心 20 →
手前の軌道線 21 → 手前の作品 24〜31**。作品はいつでも軌道線より上に来るので、
線がサムネイルを横切ることはありません。
軌道線も手前半分と奥半分で別々の `<svg>` に分け、同じレイヤー構成で前後へ
振り分けています（円を透視で落とすと単純な楕円にならないため、CSS の楕円ではなく
点を打って描いています）。見た目は前後で変えていません（同じ色・同じ太さ）。
**中心の丸に重なる範囲を描かないのは奥側だけ**です。手前側は丸より上のレイヤーに
あるので、隠す必要がなく、そのまま丸の上を通って描かれます
（最初、手前側にも同じ除外をかけてしまい、見下ろし角によっては
線が途中で切れて見える不具合になっていました）。円は自分の軸で回しても
形が変わらないので、横回転では引き直さず、見下ろし角が変わったときだけ描き直します。

**カメラは上下左右に振れます**（`wireDrag`）。横に引くと `yaw`、縦に引くと `pitch`。
真上から見下ろすところ（`pitch` 88°）まで振れるので、奥の作品が回ってくるのを
待つ必要がありません。中心の位置は動かさず、絵の向きも変えません
（いつでもこちらを向いたまま）。視点を動かすと画面下に「カメラをリセット」が
せり上がり、押すと 0.76 秒かけて既定の角度へ戻ります。

**クリックとドラッグの切り分け**：`setPointerCapture` は使っていません。
使うと `click` の宛先が `#scene` に変わってしまい、作品をクリックできなくなります。
かわりに 5px 動くまでは「クリック」として扱い、それを超えたらドラッグに切り替えて、
離した直後の `click` だけを打ち消しています。

**線は作品の丸とも重なりません。** 最初はパスの点を毎コマ削り直す
方式でしたが、角度のサンプリング（2度刻み）でしか判定できないため、
線が段々になって消える・現れるがカクついて見えました。
**SVG の `<mask>` に切り替えています。** ぼかしのかかった放射グラデーションの
円を、中心と各作品の位置に重ね、円の座標・半径を毎コマそのまま動かすだけです。
円の位置は作品の連続的な動きに直結しているので、線は角度の刻みに縛られず
なめらかに透明になります。線の形そのもの（`ringPath` の出力）は
見下ろし角が変わったときしか再計算しません。

**左右の継ぎ目（手前と奥がちょうど入れ替わる点）は、必ず同じ座標で
つながる**ようにしています。厳密な不等号（z>=0 / z<0）で振り分けると、
ちょうど境界の点をどちらか片方しか含まず、継ぎ目に小さなすき間が
できていました。境界に許容誤差を持たせ、両方の経路に含めています。

**輪の定員**は式ではなく `worstGap` で実測します。36 通りの位相で全組み合わせを測り、
直径の 0.26 倍のすき間が残らない配置は採用しません。入らなければ作品を少しずつ小さくし、
それでも入らなければ外側にもう1本の輪を足します（`planShells`）。

**衛星の中身＝作品のサムネイル画像**です。`.lens` という円い枠にはめ込み、
縁をそのジャンルの色（`--cg`）で締めています。`--cg` は作品ごとにずらさず
`config.js` の `hue` そのままなので、色を見れば所属ジャンルが分かります。

**枠の中で絵を 1.12 倍しています。** 上下に黒い余白が残らないようにするためです。
YouTube のサムネイルも `hqdefault`（4:3 の額縁に 16:9 を入れたもので黒帯が焼き込まれている）
ではなく `mqdefault`（素の 16:9）を取ります。拡大は `.lens` が切り抜くので枠は太りません。
取得できなかった作品だけ `thumbs.js` が代替の絵を描きます。ジャンルごとに絵柄が違い
（音楽＝波形、映像＝フィルム、プログラミング＝コード行、モデリング＝立方体、その他＝図形）、
作品名のハッシュで細部が変わるので、同じ絵が並ぶことはありません。

**ページの切り替え**は「食」に合わせています。前の面は奥へ引いてぼけながら消え、
次の面は中心から円で開きます（`ecOut` / `ecIn`）。View Transitions が使える環境は
CSS の `@view-transition` に任せ、使えない環境では `site.js` が同じ動きを `body` に当てます。
JS は「対応している」ではなく**「対応していない」方に印（`.novt`）を付けます** —
印が付く前の一瞬に代わりの動きが走ってしまうのを避けるためです。
`prefers-reduced-motion` のときは短い明滅だけになります。

**星** も `site.js` が撒きます。最小間隔 76px を守る棄却サンプリングなので固まりません。
作品一覧だけは `app.js` が自前で撒きます（太陽系の再配置と同時に撒き直すため）。
